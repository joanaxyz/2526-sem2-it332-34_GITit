# Frost Form Ledger Chapter Ownership Implementation Plan

**Intent:** Advance the codebase-maintainability goal by replacing the largest remaining authored curriculum monolith with chapter-owned modules behind its stable public contract.
**Current Behavior:** `backend/curriculum/seed_data/source/adventure_level_specs/v3_frost_form_drills.py` is a 2,948-line, 132,710-byte ledger that owns Frost-only fixtures, all nine chapter drill/workflow catalogs, and final composition. A maintainer changing one chapter must navigate the complete story ledger, while no guard prevents cross-chapter dependencies or monolith regrowth. Its two external consumers import only `v3_frost_form_drills.LEVELS`.
**Expected Outcome:** A same-stem `v3_frost_form_drills/` package owns Frost content through one private fixture module, nine chapter modules, one private ordered catalog, and an export-only initializer. Each chapter owns only `DRILLS`, `WORKFLOWS`, and chapter-local helpers. The public import path and `LEVELS` contract remain unchanged; chapter modules do not import one another; package internals are private; the old `.py` monolith is absent; serialized curriculum outputs are identical.
**Target-Perspective Output:** A curriculum maintainer can identify the exact file for any Frostbound chapter from the package manifest, change chapter 6 without opening unrelated chapters, inspect Frost-only repository fixtures in one place, and run the integrated curriculum-layout command to reject a restored monolith, manifest drift, cross-chapter imports, external internal imports, catalog drift, or module growth. Evidence maps every chapter to its owner and records exact before/after list and catalog hashes.
**Truth Owner:** `_fixtures.py` owns Frost-only state builders; each named chapter module owns its `DRILLS`, `WORKFLOWS`, and local helpers/constants; `_catalog.py` alone owns ordered `LEVELS` composition; package `__init__.py` is the sole public export surface. Existing neutral `advanced_story_support.py` and `form_drill_support.py` retain cross-story mechanics.
**Contract Boundary:** Preserve the import `curriculum.seed_data.source.adventure_level_specs.v3_frost_form_drills.LEVELS`, exact order/content of all 18 source lists and 112 Frost levels, all 663 composed Adventure levels, all 26 derived `V3_FORM_CHALLENGES`, curriculum seed behavior, generated targets, database/API/frontend contracts, and authored copy. Existing callers do not change.
**Cutover:** Replace the file with a same-stem package atomically. Create all private owners and the export-only initializer, validate hashes through the unchanged caller path, then delete the monolithic file. No caller migration or deprecation window is required.
**Displaced Path:** `v3_frost_form_drills.py` must be absent. No compatibility file, alternate catalog, second `LEVELS` aggregate, prefix-specific aggregate export, cross-chapter import, or external import of `_catalog`, `_fixtures`, or a chapter module may remain.
**Value Density:** This removes the largest remaining non-generated authored curriculum file, converts nine independently edited chapters into explicit owners, preserves the exact two-consumer boundary without churn, and adds an integrated anti-regression gate without changing product behavior or generated data.
**Acceptance Evidence:** Current dirty-worktree hashes for all 18 lists and three composed catalogs; status/existence/size/SHA-256 for every pre-existing planned file and every explicitly protected caller/support/generated file; a compressed machine-readable manifest of all 381 dirty paths outside the allowlist; old/new ownership and import maps; exact all-file package manifest and module line counts; negative checker fixtures for every displaced-path/topology rule; one persistent verifier that replays exact content and worktree preservation; focused curriculum tests; Ruff; generated-target check; fast repository quality gates; and a maintainer lookup table.
**Evidence Lane:** Dirty-worktree content/protection baseline -> topology guard and mutation corpus -> fixture/chapter extraction -> private catalog and same-path cutover -> monolith deletion -> persistent verifier replay of 18 lists, three catalogs, generated bytes, protected files, and outside-allowlist manifest -> focused curriculum/pedagogy tests -> Ruff -> generated-target check -> fast quality gates -> final diff and maintainer evidence.
**Kill Criteria:** Old `.py` monolith absent; exact twelve-file package manifest across every regular file except runtime `__pycache__` contents; initializer at most 10 lines and export-only; catalog at most 50 lines and composition-only; fixtures at most 225 lines; chapter-specific caps enforced; exact single top-level symbol ownership with no executable side-effect/destructuring statements; one `LEVELS` definition; zero wildcard or cross-chapter imports; zero external imports of internals anywhere under repository `backend` or `scripts`; no content dictionaries in initializer/catalog; no duplicate fixture/helper truth; no displaced neutral-support aliases anywhere in the package; all 18 list hashes, three composed catalog hashes, generated-target hash, seven protected-file fingerprints, and the 381-entry outside-allowlist manifest unchanged; no caller, database, API, frontend, generated-target, migration, or unrelated asset edit.
**Architecture Slice:** Human-authored Frost form-drill source, the existing curriculum layout checker, focused mutation tests, the existing reusable-ledger topology test, and evidence only.
**Plan Review Gate:** Requires PRE review before execution.

`PRE_SLICE_BASELINE.json` and `PROTECTED_BASELINE.json` become immutable execution inputs immediately after PRE approval. Execution and review may read them but must not modify or regenerate them.

- The layout checker rejects every expected fixture/helper binding defined by a second module and every unexpected top-level function/class/assignment in a leaf, fixture, catalog, or initializer.

## Non-goals

- Reauthoring, correcting, or restyling curriculum content.
- Changing chapter/adventure/challenge ordering, slugs, variants, checks, or copy.
- Splitting Skyline, Advanced Workflow, Blueprint, Progress, or legacy ledgers.
- Renaming the public import path or `LEVELS` contract.
- Generalizing Frost-only fixtures without proven cross-story reuse.

## Risk if wrong

A mechanical move can silently reorder levels, alter Python binding lookup, change derived Challenges, or leave a hidden duplicate import path. Exact current-state list/catalog hashes, topology mutation tests, unchanged consumers, old-file deletion, and generated-target identity are blocking evidence, not optional checks.
