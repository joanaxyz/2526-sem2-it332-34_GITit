# Mastery KPI Retrofit Implementation Plan

**Intent:** Implement the five approved learning KPIs in the supplied proposal, with concise code names and documented mathematical “Let” definitions.
**Current Behavior:** SCR/HLCR count runs, CAR counts processable submissions, ARC sums retry indices, and RTA looks for changed retries after failure.
**Expected Outcome:** Completion measures mastery once per tier, CAR uses a validated reference on the first mastery run, ARC counts unsuccessful attempts before mastery, and RTA preserves the first reserved unseen transfer attempt.
**Target-Perspective Output:** Learner and Admin receive the same server-owned definitions; researchers can create a fixed study manifest and export an immutable cutoff report with participant-balanced scores and missing-data counts.
**Truth Owner:** Backend progress services and immutable checkpoint records; adventure services own run lifecycle and reference snapshots.
**Contract Boundary:** Existing performance API RateMetric values, updated sample metadata and module CAR; generated OpenAPI remains authoritative. Formal studies use a documented Django management command.
**Cutover:** Replace executable old KPI aggregation and shared display copy together. Do not infer historical CAR or transfer outcomes from old retry indices or variant IDs.
**Displaced Path:** Processability CAR, run-denominator SCR/HLCR, retry-index ARC, and failure-triggered RTA are removed from performance reporting. Existing activity/session counts remain diagnostics.
**Value Density:** Reuse verified command accounting, first mastery events, existing replay tooling, and existing start/submit/discard routes.
**Acceptance Evidence:** A persisted hard-tier history Failure → Success → Failure → Success → Success, reference 3 and actual 4, plus a successful first novel transfer checkpoint returns SCR 100, CAR 75, HLCR 100, ARC 2, RTA 100. Later retries/replays cannot rewrite it. A frozen study export includes unattempted assignments and equally weighted participants.
**Evidence Lane:** Deterministic Django/API fixture and saved JSON report; focused backend and frontend tests; migration, contract and architecture checks.
**Kill Criteria:** No old performance formulas, frontend calculations, invented historical assessments, or shared-budget fallback for CAR remain. Unknown benchmarks and unavailable transfer content stay explicitly unscored.
**Architecture Slice:** adventures/models.py and tier services; progress/models.py, services/metrics.py and new focused reference/checkpoint/aggregation/study services; progress management command; serializers; shared performance copy and its consumers; architecture and methodology documentation.
**Plan Review Gate:** Requires PRE review before execution.

## Constraints

- Preserve all pre-existing dirty changes, especially tier_command_processing.py. Main agent owns all implementation.
- Do not rename persisted/public legacy fields gratuitously. New names use `ref_count`, `ref_hash`, `actual`, `passed`, `kind`, `study`; the methodology maps these to full definitions.
- No production database edits, curriculum reseeding, external publication, or research conclusions are needed for this change.
- Transfer variants require explicit reservation and a content-author rationale, structural difference and no prior exposure; a new ID alone is insufficient. Existing history is checked before a checkpoint is assigned. Lack of suitable content is missing data, never a guessed transfer result.
- Default learner progress uses unique attempted required tiers; formal studies freeze assigned tiers, participants, requirements, references, module weights, and cutoff in their manifest. No new curriculum expands an existing manifest.
- A first mastery CAR checkpoint is immutable even if completion's best-star pointer changes. Successful required repetitions do not increase star retry penalties.

## Ordered tasks

1. Add reference, run snapshot, checkpoint and study storage with additive migrations. Implement reference replay validation and hash invalidation. Verify migration drift and deterministic references, including optional diagnostics.
2. Integrate immutable first mastery capture, genuine-failure star semantics, reserved variant selection, transfer launch, and preserved transfer outcomes on submit/discard. Verify lifecycle tests and failed/unattempted checkpoints.
3. Replace performance aggregation, objective CAR and cohort aggregation. Add sample coverage, module CAR, fixed study manifests and freeze/export management workflow. Verify same learner/Admin values, date cutoff, missing data, fixed assignments and equal participant weights.
4. Update shared learner/Admin descriptions, evidence units and module rendering without changing names or thresholds. Regenerate contracts. Document formulas with Let definitions, author/researcher commands, migration and historic-data limitations.
5. Run correctness/maintainability/POST review and verifier roles. Save target-perspective JSON evidence and check results here. Repair important findings before delivery.

All implementation tasks are sequential in the main agent. Read-only exploration and review have no write scope.

## Execution details resolved during PRE review

- `AdventureLevelTierProgress.exposure_complete` defaults false for existing rows; only newly created progress with durable exposure tracking can certify novelty. Record every launch, including empty discarded launches, in a unique player/variant exposure row. Check every prior exposure against canonical repository fingerprints. Historical rows without complete evidence do not receive transfer checkpoints.
- Transfer is an explicit `transfer` input on the existing tier start endpoint after the same access checks. It requires mastery, a reserved variant with an authored reason, and an assigned checkpoint with no prior run. Transfer runs are separate from practice/replay for rewards, mastery counters, stars and KPI eligibility. Meaningful abandonments close the checkpoint; empty starts retain their first run/checkpoint rather than erasing exposure.
- Dashboard SCR/HLCR/ARC and chapter KPIs delegate to the same revised performance owner; activity counters and the separately named Stats finish-rate diagnostic retain run semantics.
- A live first-mastery CAR checkpoint uses the validated reference captured at run launch. Missing historical references are not reconstructed. A formal study assigns CAR even when mastery is absent; at cutoff an uncompleted assignment scores zero, while a completed assessment with missing reference evidence is reported missing.
- Studies snapshot curriculum requirements, allowed variant/reference hashes, transfer assignments, explicit participant IDs, cutoff and module weights before data collection. They use outcomes ended before the cutoff, never a later mutable run status. Freeze is allowed only after cutoff and is idempotent; exports read the saved report after freezing. A changed manifest cannot overwrite an existing version.
- All new/modified API keys are required server fields; update frontend fixtures and consumers with generated types. Sample evidence distinguishes tier counts, mean percentage scores, contributing participants, unattempted assignments and genuinely missing data.

Verification commands: `backend/.venv/Scripts/python.exe -m pytest progress/tests adventures/tests -q` (backend cwd); `python manage.py makemigrations --check --dry-run --settings=config.test_settings`; `python scripts/generate_api_contract.py`; targeted Vitest plus `npm run build`; repository API, architecture and documentation guards. Reference validation uses existing real browser-engine replay, then the backend completion evaluator, before persisting a signed reference count. Reviews use read-only agents and no implementation delegation.

## Implementation appendix

Final PRE clarifications: runs and checkpoints snapshot `ref_hash` alongside `ref_count`. KPI-specific module domains are SCR/CAR/HLCR/ARC Modules 1–4 and RTA Modules 3–4; overall weights are normalized over each KPI's eligible assigned module domain. An eligible positively weighted module lacking evidence makes that overall score null. Modules without assigned applicable tiers are explicitly outside the study's domain. RateMetric may carry optional `unit: participants` for cohort means; shared evidence copy uses that to avoid treating participant means as tier counts.

1. Storage: `adventures/models.py` adds nullable `ref_count`, `ref_hash`, `assess_diag`, `is_transfer`, `transfer_note` to tier variants; runs snapshot `ref_count`, `assess_diag`, `is_transfer`; progress adds `exposure_complete`. `progress/models.py` adds `KpiExposure` (unique player/variant, canonical state key), `KpiCheckpoint` (unique player/tier/kind; protected nullable first run and reserved variant; nullable reference/actual/passed, retries, assignment/end timestamps), and `KpiStudy` (unique slug/version identity, manifest, cutoff, nullable frozen report). Add migrations to each app; no existing rows receive invented benchmarks/checkpoints.
2. Owners: new `progress/services/references.py` hashes relevant initial/target states, evaluation spec, authored solution and workspace edits, diagnostic policy and counting version. `curriculum/services/solution_replay.py` owns the existing Node replay subprocess extracted from `generate_targets`; both commands reuse it. `progress/management/commands/kpi_refs.py` validates references and explicitly reserves reviewed variants with a reason, with at least one ordinary variant left. Positive reference counts are accepted only after backend completion evaluation succeeds. Zero counted routes require explicitly assessing Git diagnostics or stay unscored.
3. Lifecycle: new `progress/services/checkpoints.py` records every launch, first mastery CAR, unseen transfer assignment and terminal transfer outcome. `adventures/services/tier_runs.py` owns explicit transfer launches, snapshots references and counts actual unsuccessful attempts for star retries. This ownership keeps runtime imports acyclic. Shared `transfer_ready` checks drive launch eligibility and available links; changed pending content is missing evidence. `tier_command_processing.py` captures mastery only when completion is first created and excludes transfer from mastery/rewards; discard records failed transfer rather than deleting it. `tier_variants.py` excludes reserved variants. Existing tier start serializer/view forwards `transfer`; performance response exposes assigned transfer tier IDs for Home Progress links through the existing tier start route. `TierStartPage` and `tierRunsApi` forward the flag. There is no automatic silent assessment launch.
4. Read owner: new `progress/services/mastery_metrics.py` receives the scoped run queryset and joins completion/checkpoint evidence once. Unique attempted required tiers are the live denominator; first completion timestamp gates mastery. ARC counts failed/submitted-command abandoned non-transfer runs before that timestamp; only mastered tiers contribute. `metrics.py` delegates performance, objective CAR and dashboard KPIs to it; ordinary session counts stay distinct. Module CAR is added.
5. Rate contract: `RateMetric.numerator` becomes float. For learner tier rates it remains mastered/successful count; ARC is failures; CAR is sum of checkpoint percentage scores. Denominator is eligible tiers/checkpoints. Admin aggregate values are means of participant scores, with numerator=sum participant values and denominator=contributing participants. Optional `unit: "participants"` identifies those means. The architecture guard pins the exact revised serializer/OpenAPI fields and optionality. Add a `samples` object (participants, attempted/mastered tiers, missing mastery evidence, assessed/missing CAR and assigned/pending/missing transfer counts) so these units are explicit. Existing labels in Admin dashboard, learner comparison, preview fixtures and shared copy are updated. Frontend never divides numerator/denominator to calculate values.
6. Formal studies: new `progress/services/studies.py` and `progress/management/commands/kpi_study.py` provide `create`, `freeze`, `export`. Create requires explicit player IDs, tier IDs, future aware cutoff and versioned slug, validates all eligible variant references, snapshots required clears/variant hashes and reserved transfer IDs and the four equal module weights (or explicitly supplied positive weights), before the participants start assigned tiers. Formal assignments live in the immutable study manifest independently of later mastery. Freeze is transactional after cutoff, checks hashes/evidence, uses only runs with outcome timestamps at/before cutoff and snapshots each participant/tier result. A not-mastered assigned CAR is zero only with a validated assigned reference; missing or changed content is missing. SCR/HLCR include unattempted assigned tiers. RTA includes assigned valid transfer checkpoints (unattempted/unfinished zero); unavailable novelty/content is missing. ARC is null when no mastery; missing module scores remain null, and weighted overall is null unless all positively weighted module scores for that KPI are observed. Report coverage and unattempted counts separately. Export returns the frozen JSON; no later practice can rewrite it.
7. Evidence paths: `progress/tests/test_mastery_kpis.py`, `test_kpi_references.py`, `test_kpi_studies.py` and updated existing KPI tests own formula, lifecycle, unequal-activity and cutoff-crossing fixtures; frontend semantics/component tests own displayed units/links. Save the persisted five-KPI example and frozen study report in `docs/goals/mastery-kpi-retrofit/evidence.json`; save review/check outcomes in `EVIDENCE.md`. Root `KPI_METHODOLOGY.md` documents Let definitions, commands, targets, sample units, historic-data policy and pre/post evaluation distinction; `ARCHITECTURE.md` links it.
